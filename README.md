# ubx-sdk-digitalocean

Typed bindings for DigitalOcean (`[dynamic_providers.digitalocean]`,
OpenAPI 3.0-sourced via `ubx-provider-dynamic`), generated by
[ubx](https://github.com/ubiquex/ubiquex) (`ubx sdk gen`), for all three
SDK languages in one combined repo:

- [`sdk/go/`](sdk/go/) -- Go bindings, module `github.com/ubiquex/ubx-sdk-digitalocean/sdk/go`
  (a subdirectory Go module, tagged `sdk/go/vX.Y.Z`)
- [`sdk/typescript/`](sdk/typescript/) -- TypeScript bindings, published to JSR as
  [`@ubx/sdk-digitalocean`](https://jsr.io/@ubx/sdk-digitalocean)
- [`sdk/python/`](sdk/python/) -- Python bindings, published to PyPI as
  [`ubx-sdk-digitalocean`](https://pypi.org/project/ubx-sdk-digitalocean/)
  (imported as `ubx.digitalocean.*`, a real PEP 420 namespace package)

59 real resource types, 137 real data source types, generated from
DigitalOcean's own real, public OpenAPI 3.0 spec
(github.com/digitalocean/openapi).

## Install

```
go get github.com/ubiquex/ubx-sdk-digitalocean/sdk/go
npm install @ubx/sdk-digitalocean
pip install ubx-sdk-digitalocean
```

## Provenance

`VERSION` at repo root records the real upstream spec source, fetch
date, and the pinned `ubx-schema-digitalocean` release this generation
came from. DigitalOcean's own real spec needs a real Redocly bundling
step before it loads at all -- see `ubx-provider-dynamic`'s own
`config.Provider.RedoclyBundle` doc comment for why.

## Depends on / depended on by

- Schema: [`ubx-schema-digitalocean`](https://github.com/Ubiquex/ubx-schema-digitalocean)
- Coordinating repo: [`ubiquex`](https://github.com/Ubiquex/ubiquex)
- Docs: [`ubiquex-docs`](https://github.com/Ubiquex/ubiquex-docs) reads
